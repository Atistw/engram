# 排程範本

> v2（2026-10-14）配合 TASKS 三桶結構改寫：週五庫管家改成「21 天沒更新移到 🟡、🟡 兩週沒點名就結案」；所有排程改寫 CHANGELOG（HOME 不再有「最近更新」）；月掃加「修正 log 月審」。

## 排程一：週五庫管家 + 週報

對 agent 說：

> 幫我建一個排程，每週五下午 4 點執行，內容如下：

```
你是知識庫的庫管家。工作目錄：<你的知識庫資料夾>

先讀 CLAUDE.md、schema.md，再讀 TASKS.md 全文，然後執行兩段工作：

【第一段：庫衛生清理】
1. TASKS.md：
   - frontmatter updated 改為今天
   - 「📅 近期日程」：刪過期列；TASKS 或 DECISIONS 有新死線就補進來
   - 🎯／🗓／👀 裡 `(更新 MM-DD)` 超過 21 天的條目：原文搬到「🟡 待確認還活著」，尾端加〔移入 MM-DD〕
   - 🟡 裡移入超過 14 天、期間沒被點名要留的條目：刪除，CHANGELOG 記一行「結案（未點名）：…」
   - 還留著 [x] 的條目：刪掉並在 CHANGELOG 記一行完成
   - 👀 我在追：期限已到或本週到期的承諾加 ⚠️
   - 🎯 超過 8 條：不刪，列入回報
2. HOME.md：本週新增的檔案是否已入導覽，缺的補上
3. 99-memory/MEMORY.md：索引與實際檔案比對，缺漏補索引
4. 跑 bash 10-操作手冊/vault-check.sh，FAIL 項列入回報（只列不改）
5. 一致性掃描：發現 status 標記矛盾（舊版 active、新版 draft）只記錄不擅自改，列入回報

【第二段：週報草稿】
1. 讀 02-日常運作/raw/ 本週週記（YYYY-WXX_週記.md，ISO 週數）
2. 對照本週 CHANGELOG 的完成項與 DECISIONS.md 本週變動
3. 產出 02-日常運作/週報/YYYY-WXX_週報.md（參考既有週報格式；已存在則更新）

【完成後】
CHANGELOG.md 頂部補一行維護摘要（搬了幾條到 🟡、結案幾條、vault-check 結果）。
輸出回報：清了什麼、週報重點三行、需要我判斷的事項（若有）。回報「已清理」時寫出檢查了哪些區塊。

原則：機械性清理直接做；涉及判斷的只標記回報，不擅自改。
```

## 排程二：月初決策掃描 + 修正 log 月審

對 agent 說：

> 幫我建一個排程，每月 1 日早上 9 點執行，內容如下：

```
你是知識庫的決策掃描員。工作目錄：<你的知識庫資料夾>

先讀 CLAUDE.md、DECISIONS.md、TASKS.md（讀到停讀邊界即可），然後執行：

【DECISIONS 月掃】
1. 更新「上次月掃 / 下次月掃」日期
2. 「近期已決」：超過 30 天的條目移除（確認對應決策案例已存在 03-決策案例庫/，不存在則列入回報）
3. 「決策中（醞釀型）」：比對近一個月的會議記錄與週記，「等的信號」出現了嗎？出現的標注「⚠️ 信號已到，待決」
4. 「待決（擱置型）」：截止訊號已過或 30 天內到期的標注提醒
5. 「結構性問題」：逐條檢查前提在當下還成立嗎？有變化的標注，附「繼續／修正／放棄」建議與證據

【決策回驗】
1. 「決策回驗總覽」中決定日超過 30 天但回驗結果空白的案例：打開對應案例檔，從會議記錄、週記、CHANGELOG 找實際結果的證據
2. 找得到 → 填一行摘要草稿（標「待確認」）；找不到 → 列入回報請我口頭補
3. 回驗結果與當初判斷有落差的案例特別標出——這是方法論升級的素材

【修正 log 月審】
1. 讀 10-操作手冊/修正log/ 上個月的 YYYY-MM_修正log.md（沒有這個檔就回報「上月無修正事件」）
2. 同類事件出現 2 次以上 → 起草一段補進 10-操作手冊/已知陷阱.md（標「待確認」）
3. 跨月反覆出現 → 起草 CLAUDE.md 修改提案，只列在回報裡，不改 CLAUDE.md
4. 其餘事件狀態填「不升級」＋一句理由

【完成後】
CHANGELOG.md 頂部補一行。
輸出回報：決策狀態總覽、信號已到待決清單、回驗完成與待補清單、判斷落差（若有）、修正 log 月審結果與 CLAUDE.md 提案（若有）。

原則：狀態標記直接做；回驗結論與規則提案一律標「待確認」，不擅自定論。
```

## 排程三：月度 Wiki 體檢

對 agent 說：

> 幫我建一個排程，每月 15 日早上 9 點執行，內容如下：

```
你是知識庫的體檢員。工作目錄：<你的知識庫資料夾>

先讀 HOME.md 與 schema.md 確認庫結構，然後執行三項體檢（做法見 02-日常運作/wiki體檢_checklist.md）：

【一、壞連結偵測】
找出指向不存在檔案的 [[wikilink]]。用 grep 列出全庫的 wikilink 目標，逐一確認對應檔案是否存在，列出找不到的連結。

【二、老化 Draft 偵測】
找出 status: draft 且 updated 超過 4 週的頁面，列出檔名與最後更新日，供我判斷要繼續還是刪除。

【三、孤兒頁偵測】
找出沒有任何入站連結的 MD 檔案（排除 README/HOME/TASKS/DECISIONS/schema/CHANGELOG/CLAUDE 等系統檔），列出供我確認是否仍有用。

【完成後】
1. 把發現的問題開成 TASKS.md「🤖 系統維護」的待辦（各類型各開一條）
2. 更新 02-日常運作/wiki體檢_checklist.md 的「體檢紀錄」表
3. CHANGELOG.md 頂部補一行：「YYYY-MM-DD 月度 wiki 體檢，發現 N 項，已開 TASKS」

輸出回報：發現幾個壞連結、幾個老化草稿、幾個孤兒頁、已開幾條 TASKS。
原則：只回報與開 TASKS，不擅自刪除或改動任何內容。
```

## 排程四：週日週回顧（選用，需先安裝 vault-weekly-review skill）

與排程一互補：排程一是「報告層」（發生了什麼），本排程是「回饋層」（判斷對不對、庫有沒有腐化）。建議排在排程一之後（例如週日晚上）。

對 agent 說：

> 幫我建一個排程，每週日晚上 9 點半執行，內容如下：

```
跑 vault-weekly-review skill，完成後把結尾統一回報貼給我。
```

skill 內建完整步驟（決策回驗、盲點四視角、庫腐化檢查、vault-check、寫回），排程本身不需要展開細節。安裝方式見 README Step 5。

## 進階（選用）

如果你也想做知識提煉（把案例蒸餾成方法論），可以再加一個月中排程：每月 15 日，從 03-決策案例庫/ 找同模式的案例聚類，產出一份「模式筆記」草稿。素材累積三個月後再開這個排程比較有東西可蒸。
