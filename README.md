# Engram

> 讓 AI 成為你的第二大腦——記得你是誰、你的工作背景、你怎麼決定事情，並且長期維護這份記憶。

## 為什麼是 Engram，而不是又一個 AI 知識庫

**最大的不同：Engram 保護「你的原話」不被大模型同化。**

我們常叫 AI 幫忙整理東西，但怎麼整理都是 AI 的視角——它的分類、它的用詞、它挑什麼擺前面、什麼略過。知識庫越整理，越是大模型的形狀；等你真要找「自己當初怎麼想的」，味道全偏了。最糟的是你會信它，因為那是「你的」庫——你甚至開始用它給你的詞來描述自己。

事實錯誤還能查證糾正；這種同化沒有一句「錯」可以指，卻一次次把你的稜角磨成通用管理語言。

Engram 用**出處分級**圈出不許被同化的保護區：

- **A｜你的原話、一手材料** — 保護區，逐字保存，不許被改寫
- **B｜AI 整理** — 譯本，自帶「我是轉譯的」標籤
- **C｜AI 推論**（含一切人物判斷）— 更遠的譯本，永不冒充成你的判斷

像翻譯：你的話翻成另一種語言再翻回來，意思在、味道沒了。AI 每次整理都是一次翻譯。分級不是為了防 AI 說錯，是為了在 AI 幫你整理得越來越順的同時，**確保你還找得回沒被它同化的自己**。

## 這套系統在做什麼？

你在資料夾裡建的是**知識庫**，AI agent 掛進來讀寫這些檔案——不限工具：Claude 的 Cowork、Claude Code、Codex，任何能讀寫本地 Markdown 的 agent 都行。效果：

- 每次開新對話，AI 都知道你是誰、現在在忙什麼、有哪些事懸著
- 你丟逐字稿，AI 自動跑完整入庫流程：會議記錄、週記、待辦更新
- 待辦（TASKS）和決策（DECISIONS）有儀表板，排程每週自動清理，不用你記得維護
- 你不需要每次重新解釋背景

**核心理念（實戰迭代的教訓）：**

1. **對話是揮發的，檔案是持久的**——產出當下就寫檔，不在對話裡暫存
2. **規則寫多處必飄移**——行為規則只放常駐指示層一處（Cowork＝偏好設定、Claude Code＝`CLAUDE.md`、Codex＝`AGENTS.md`）
3. **靠記得 = 不會發生**——例行維護交給排程，不靠自律
4. **「要做的事」和「要想的事」分開管**——TASKS 管行動，DECISIONS 管決策
5. **閘門要少，而且要從事故長出來**——大段流程文字（「先觀察再回答」之類）實測幾乎攔不到真實錯誤，真實錯誤多是內容錯：讀錯數字、認錯人、專名誤植。所以常駐層只留幾條短閘門，每條都對應一個真實事故（見 `10-操作手冊/已知陷阱.md`）；新規則靠修正 log 每月審一次再長，不預先堆
6. **skill 只留一份正本**——同一個 skill 散在多個位置，改了正本、部署版沒重裝，新規則就安靜失效。正本放 `_skills/`，部署只留一處，vault-check 會抓落後

> 已經在用舊版？看 [UPGRADE.md](UPGRADE.md)，不用重新複製整個資料夾。

## 不需要另裝紀律框架

早期版本建議搭配另一個流程框架（強制多方抗辯、固定思考步驟）。作者自己的庫後來拆掉了那套常駐流程，改把需要的紀律收進 `CLAUDE.md` 的幾條短閘門：凡是會讀 `CLAUDE.md` 的 AI 工具都適用，覆蓋面比只掛在單一工具上的流程大。目前的閘門是：

- **證據**：先讀檔再下結論；宣告完成時說清楚驗了什麼、沒驗什麼。
- **完成前驗收**（選用）：重要產出交給一個沒看過對話的驗收子代理，只有它判 CONFIRMED 才算完成。

知識庫的污染會複利：今天寫進未驗證的判斷，下次讀回就被當成事實。所以驗收要擋在寫入口。

## 第一次設定（約 40 分鐘）

### Step 1：複製資料夾
把整包內容複製到你自己的位置，改名（例：`yourname-knowledge-base`）。

### Step 2：讓你的 agent 掛上這個資料夾
- **Cowork**：Claude 桌面 App → Cowork → 選擇資料夾 → 指向你的知識庫
- **Claude Code**：在知識庫資料夾裡開 `claude`，它會自動讀根目錄的 `CLAUDE.md`
- **Codex／其他 agent**：在資料夾裡啟動，指向它作為工作目錄

### Step 3：填基本背景
打開 `99-memory/MEMORY.md`，照註解填寫（10 行內）。這是 AI 的輕量工作記憶。

### Step 4：設定常駐指示層（最重要的一步）
打開根目錄的 `CLAUDE.md`，照檔頭註解改成你的情況：把 `<使用者>` 換成你的稱呼，刪掉標「選用」但你用不到的條目。
- **Claude Code**：直接用這份 `CLAUDE.md`，每個 session 自動載入
- **Codex**：複製一份改名 `AGENTS.md`（兩份都留的話，改一份要同步另一份）
- **Cowork**：把 `CLAUDE.md` 全文貼進「設定 → 個人偏好」，開頭加一行「工作目錄：專案下的 <你的知識庫資料夾名>」

**這裡是行為規則的唯一權威來源**——寫在一般檔案裡的規則長對話後會被遺忘；常駐指示層每輪都在。`CLAUDE.md` 目前收的閘門：

| 閘門 | 防什麼 |
|------|--------|
| 出處分級 | AI 的整理稿被讀回來當成你的原話 |
| 證據 | 沒讀檔就下結論；「已驗證」其實只驗了格式 |
| 人事阻尼 | 談人事時，AI 的用詞一路把你的框架推得更尖銳 |
| 外送外部模型（選用） | 去識別時把決策結構一起刪掉，或把不該出境的內容送出去 |
| 大決策（選用） | 大決策沒對照你自己寫好的決策原則 |
| 入庫／寫回／被更正時／不覆述 | 日常規則：逐字稿走 skill、產出當下落檔、被更正就記修正 log |

每條閘門背後的事故寫在 `10-操作手冊/已知陷阱.md`。想改閘門，先讀那份。

### Step 5：安裝 skill
`_skills/transcript-intake/` 是逐字稿入庫流水線。請你的 agent：
> 「把 _skills/transcript-intake 打包成 .skill 給我安裝」

安裝後丟逐字稿就會自動觸發。想客製（加自己的掃描規則）先改 `_skills/` 裡的正本再打包，不要直接改安裝後的那份——兩份一分岔，vault-check 第 7 項會報 FAIL（只檢查 Claude Code／Codex 的安裝位置；Cowork 裝的 skill 要自己記得重裝）。

（選用）`_skills/vault-weekly-review/` 是每週回饋層掃描（決策回驗、盲點四視角、庫腐化檢查），與週報排程互補。打包安裝方式同上，搭配 Step 6 的排程四使用。

### Step 6：建立排程（自動維護的關鍵）
打開 `_schedules/排程範本.md`，把排程的 prompt 依說明貼給你的 agent 建立：
- **週五庫管家+週報**：每週把 21 天沒更新的待辦移到「🟡 待確認」、兩週沒點名的結案、跑 vault-check、從週記生成週報
- **月初決策掃描**：每月掃 DECISIONS、提醒回驗到期的決策、審上個月的修正 log
- **月度 Wiki 體檢**：每月偵測壞連結、老化草稿、孤兒頁，自動開成 TASKS 項
- **（選用）週日週回顧**：需先裝 vault-weekly-review skill，每週驗證判斷有沒有走樣、庫有沒有腐化

Cowork 建好後對每個排程按一次「Run now」預核檔案權限；Claude Code／Codex 可用系統 cron 掛 `_schedules/` 裡的 shell 腳本。

### Step 6.5（選用）：git 版本控制

雲端同步（OneDrive/iCloud）只保留最新版，沒有變更軌跡。加 git 後你就有完整歷史：

```bash
cd "/path/to/your-knowledge-base"
git init -b main
git config user.name "你的名字"
git config user.email "你的信箱"
git add -A
git commit -m "init: knowledge base"
```

套件已附 `.gitignore`（排除 Obsidian workspace cache 與 OS 暫存檔），直接使用即可。

**雲端同步共存注意**：commit 完成後再讓同步跑；不要在同步期間 commit，否則可能產生衝突檔。

### Step 6.6（選用）：Obsidian Dataview 自動索引

如果你用 Obsidian，安裝 **Dataview** 插件後，各分類的 MOC（知識地圖）可以用 query 取代手動維護的清單——新增文件會自動出現，不需要每次手動更新索引。

安裝方式：Obsidian → 設定 → 社群插件 → 搜尋「Dataview」→ 安裝並啟用。

安裝後對 AI 說：「幫我把 [某個 MOC] 的手動清單改成 Dataview 自動 query」，它會依你的 frontmatter 結構生成對應的 query。

> **注意**：Dataview 只在 Obsidian 裡渲染，純文字編輯器或 AI 看到的是 code block 原始碼，屬正常。

### Step 6.7（選用）：effort-tier mod（自動調整 Claude Code 思考檔位）

只用 Claude Code 桌面版、且版本支援 mod 時才有用。它在每個請求送出前，依你這一輪的提問自動調整思考檔位：人事與決策類的題目抬到 `high`，純機械雜務降到 `low`，**不換模型、不連網**。規則是關鍵字比對，詞可以在設定檔裡自己加。

安裝與設定見 `_mods/effort-tier/README.md`。它是 `CLAUDE.md`「模型檔次（選用）」的機械版，兩者可並用。

### Step 7：第一次對話驗收
> 「我已照 README 設定完成，讀 99-memory/MEMORY.md 和 HOME.md，告訴我你對我的理解，然後幫我把當前 3 個最重要的待辦寫進 TASKS.md。」

## 資料夾結構

```
你的知識庫/
├── README.md            ← 本文件：庫結構與初始化（不放行為規則）
├── CLAUDE.md            ← 常駐指示層：行為規則唯一來源（Codex 改名 AGENTS.md）
├── UPGRADE.md           ← 舊版升級指南
├── HOME.md              ← 主導覽，AI 找資料的起點
├── TASKS.md             ← 待辦儀表板（要做的事）
├── DECISIONS.md         ← 決策追蹤（要想的事、要決的事）
├── CHANGELOG.md         ← 唯一完整的變更軌跡（新條目插最上方）
├── schema.md            ← 頁面型態、frontmatter、命名規則
├── _templates/          ← 文件模板（會議/決策/產品/人物）
├── _skills/             ← skill 原始檔（打包安裝用）
├── _schedules/          ← 排程 prompt 範本
├── _mods/               ← （選用）Claude Code mod 原始檔，裝在 ~/.claude 而非知識庫內
├── 00-核心定位/          ← 你是誰、工作邊界、核心方向
├── 01-組織與關係/        ← 關鍵人物、組織結構
├── 02-日常運作/          ← 會議記錄/ 會議準備/ 週報/ raw/（週記流水帳）/ 回顧/（選用）
├── 03-決策案例庫/        ← 重要決策的完整思路（可查前例）
├── 04-專案/             ← 長期專案文件
├── 05-產品或業務/        ← 你負責的產品線或業務
├── 10-操作手冊/          ← 已知陷阱、專名消歧登記表、修正log/、vault-check.sh
└── 99-memory/           ← 跨對話記憶層
```

資料夾名稱可改（`99-memory/` 建議保留），但 **HOME / TASKS / DECISIONS / schema / CHANGELOG / CLAUDE 六個系統檔與 `10-操作手冊/` 請保留檔名**——排程、skill、vault-check 都認這些名字。

## 日常工作流程

| 情境 | 你做什麼 | 系統做什麼 |
|------|---------|-----------|
| 開完會 | 丟逐字稿（建議上傳檔案，不要貼上） | skill 自動：會議記錄 + 週記 + 待辦/決策候選 |
| 突發事件/重要對話 | 貼給 AI 或口述 | 自動 append 當週週記、更新 TASKS |
| 做了重要決策 | 說「這個建決策案例」 | 用模板建檔進 03-決策案例庫，DECISIONS 登記 |
| AI 做錯被你糾正 | 直接說哪裡錯 | AI 明說這是 surprise，記一列進當月修正 log；月掃時同類 2 次以上就補進已知陷阱 |
| 每週五 | 不用做事 | 排程清理儀表板 + 出週報草稿 |
| 每週日（選用） | 看排程回報 | 排程跑週回顧：決策回驗、盲點四視角、庫腐化檢查 |
| 每月初 | 看排程回報 | 排程掃 DECISIONS、提醒該回驗的決策 |
| 每月中 | 看排程回報 | 排程跑 wiki 體檢：壞連結、老化草稿、孤兒頁自動開成 TASKS |

**即時寫回協定**：對話中產出有意義的內容（文件、判斷、狀態變化），當下立刻寫檔，`CHANGELOG.md` 頂部加一行。改版時更新 `updated`/`version`，舊版標 `status: archived`。`status: draft` 是唯一的「勿用」信號——持續在改的文件仍是 `active`。

## 三份儀表板怎麼分工

| 檔案 | 管什麼 | 更新者 |
|------|--------|--------|
| TASKS.md | 要做的事，三桶：🎯 我要做（上限 8）／🗓 我要開的會／👀 我在追（一人一行）；停讀邊界以下是 🟡 待確認與 🤖 系統維護 | AI 每次互動（先對帳再寫）+ 週五排程 |
| DECISIONS.md | 要想的事：醞釀型/擱置型/結構性問題/決策回驗 | AI 識別 + 月初排程 |
| HOME.md | 純導航，不放更新紀錄 | 新增分類或系統檔時 |
| CHANGELOG.md | 唯一完整的變更軌跡，完成的待辦也記在這 | 每次改檔當下 |

**TASKS 為什麼這樣設計**：待辦清單最常見的死法是越堆越長，最後沒人讀。三條規則讓它保持短：每條帶 `(更新 MM-DD)`，21 天沒動就被移到 🟡；🟡 兩週沒人點名就結案；完成就刪，不留「已完成」區。開新對話時 AI 只讀到停讀邊界，啟動成本固定。

## 常見問題

**Q：一定要 Obsidian 嗎？** 不用，純 Markdown 資料夾即可；Obsidian 的 wikilinks 和 Graph View 是加分項。

**Q：為什麼 CLAUDE.md 閘門這麼少？要不要多加幾條？** 先別加。作者的實測是：一段「先讀現況再回答」的提醒每輪注入，生效的兩週內十次審查有七次被擋回，理由正是「沒讀現況」——提醒沒攔住它要防的事。想加規則的時機是修正 log 裡同類錯誤出現兩次以上，而且你能說出它對應哪個事故。

**Q：AI 忘記規則怎麼辦？** 規則只該在常駐指示層（偏好設定／`CLAUDE.md`／`AGENTS.md`，每輪或每 session 重新載入）；觸發型流程在 skill（觸發當下載入）。如果你發現自己把規則寫進 README 或記憶檔——那就是飄移的開始，收回常駐指示層。

**Q：長逐字稿怎麼給？** 上傳檔案而非貼上。貼上的文字永久佔據上下文，上傳的檔案 AI 可以分段讀。

**Q：排程沒跑？** 排程靠你的 agent 環境驅動：Cowork 排程只在 Claude App 開著時跑（關著下次補跑）；Claude Code／Codex 可用系統 cron 掛 `_schedules/` 裡的腳本。

## 開始吧

Step 1 複製資料夾 → Step 4 的常駐指示層是成敗關鍵，別跳過。
