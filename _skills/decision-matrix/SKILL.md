# 決策矩陣（加權評分法）

目的：把「我比較想要哪個」拆成可檢查的指標，讓偏好攤開，不是替使用者做決定。

## 流程（依序，不跳步）

1. **確認選項與一票否決條件。** 先問或確認：有哪些選項（2–5 個）、有沒有硬條件（預算上限、必須支援的規格、期限）。不符硬條件的直接淘汰，不進矩陣。
2. **列指標，5–10 個。** 使用者沒給就依情境擬一份草稿請他刪改；每個指標要能被打分（避免「整體感覺」這種大雜燴）。同類指標別重複計（例如「重量」「好攜帶」只留一個）。
3. **先給權重，再打分數。** 權重 1–5 代表在意程度。順序不可顛倒：看過分數再調權重，容易調成想要的答案。
4. **打分 1–5。** 5 = 該指標上最好。分數要有依據：能查到的規格／價格／實測，用數據換算並註明來源；只能主觀的，標「主觀」。查不到的標「待查」，不要編。
5. **算加權總分** = Σ（分數 × 權重）。用表格列出計算過程（每格 分數×權重），最後附總分與排名。有多格或數字多時用程式算，避免心算錯。
6. **敏感度檢查（必做）。** 至少做兩項：
   - 把權重最高的指標權重 ±1，排名是否翻轉？
   - 領先選項與第二名差距 < 10%（總分差 / 滿分）時，直接說「差距在誤差內，矩陣分不出來」。
7. **對照直覺。** 問使用者：結果和你原本傾向一致嗎？不一致就追問是不是漏了指標（品牌、人際、後悔成本、轉換成本），補進去重算一次。
8. **收尾。** 講：矩陣分數結論、最敏感的假設、還沒驗證的項目（標「待查」「主觀」的有哪些）。

## 輸出格式

```
一票否決：…（已淘汰：…）

| 指標 | 權重 | A | B | C | 依據 |
|---|---|---|---|---|---|

加權總分：A = … ｜ B = … ｜ C = …（滿分 = 5 × 權重和）
敏感度：…
漏掉的指標？：…
結論：…（含未驗證項目）
```

## 紀律

- 不替使用者偷偷定權重；權重由他給，或明確標「我的草稿，請你改」。
- 不為了湊出明確贏家而調分數。差距太小就照實說。
- 涉及人事任免、接班、超過金額門檻、對上承諾、越級：有個人決策原則檔就先引條文（見 `CLAUDE.md`「大決策」），矩陣只當整理，不下「就選 X」的結論，標「待使用者拍板」。
- 人物打分（例如比較人選）屬未確認的人事判斷，一律標「待確認」，不得把模型推測當成使用者的看法。
- 結果要存時：寫成 md 放 `03-決策案例庫/`（用決策案例模板），或使用者指定位置；沒要求就不寫入庫。
