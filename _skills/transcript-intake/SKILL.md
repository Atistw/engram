# 逐字稿入庫流水線

把一份逐字稿／群聊／情境描述，一次處理完所有該落地的產出。知識庫根目錄：你的 agent 掛上的知識庫資料夾（以下路徑相對於庫根目錄）。

## 執行順序（依序跑完；不適用的步驟回報「N/A」，不默默略過）

### 步驟 0｜判斷輸入型態
- **會議逐字稿／錄音摘要** → 跑全部步驟
- **群聊片段／口述情境** → 跳過步驟 1，從步驟 2 開始
- 長檔案：分段讀取，不要求使用者重貼

### 步驟 0.5｜專名消歧（寫任何人名／客戶名／產品名前的前置閘門，不可跳）
逐字稿的 speaker 標籤與稿內專名（人名、客戶／公司名、**產品／平台／系統名、業務流程名詞**）都是 ASR 產物，一律當**待查實體**：不是雜訊、不靠語境自行還原、不靠「被點名者＝下一個發言者」這類相鄰關係推定身分。每個待查實體寫定前都要比對既有寫法。
- **比對來源**：人名 → 人物圖譜；客戶名 → 既有客戶清單／前次會議記錄；產品名與業務名詞 → grep 知識庫既有用字（這兩類沒有名冊擋，寫錯會安靜污染往後的檢索與寫回，一定要 grep）。已知易混組查 `10-操作手冊/專名消歧登記表.md`（正本）；讀不到知識庫時讀 skill 內附的 `references/專名消歧登記表.md` 快照。**新變體只補正本**；寫不進知識庫時，列在回報的「待補登記表」。
- **語境讀得通不是正名依據**：ASR 詞放進上下文讀得通，不代表它是對的。庫內沒有對照可查的業務名詞／產品名，一律標「(ASR待正名)」。只有兩種情況可以定案：(a) 庫內既有寫法比對相符；(b) 使用者或說話者本人明確確認。
- **音近變體先假設同一實體**：音近的兩個專名散在稿內不同段，先假設是同一個、回稿核對，不預設是兩個（誤裂比誤合更難察覺）。
- **多份逐字稿互相衝突時不各自定案**：同一場會議有兩份以上獨立轉寫，對同一實體或數字給出不同結果時，不依任一份逕自定案。兩份原檔都保留，正文標「來源衝突，待核對」，核對過原始資料才收斂。
- **殘餘歧義**：在**簡報正文就地**標「(ASR待正名)」，不只在文末加註腳（註腳擋不住讀正文的人）。
- **完成準則**：每個待查實體都結案（比對相符／grep 命中既有寫法／標 ASR待正名），無漏；數量在結尾回報。

### 步驟 1｜會議記錄（僅會議類輸入）
依 `_templates/會議記錄.md` 產出，重點放判斷層：
- 本次方向確認（這場會議定調了什麼）
- 決議事項與待辦（誰、做什麼、何時）
- 卡點與決策缺口（哪些事需要使用者出手）
- **與會者行為紀錄**：記具體的發言、動作，以及它直接造成什麼；不打分數、不評價人。本場對會議重要但素材不足的人，只寫「本場樣本不足，不判定」。
- 存入 `02-日常運作/會議記錄/YYYYMMDD_主題.md`（frontmatter 依 schema.md）

### 步驟 2｜週記 append
重要事件（突發事件、重要決策、組織信號）append 到 `02-日常運作/raw/YYYY-WXX_週記.md`（ISO 週數；不存在則建立）。
- 格式：`- YYYY-MM-DD｜[事件類型]｜一行摘要`
- 只記週報層級的事件，不是每句話都記

### 步驟 3｜決策案例候選掃描
觸發條件（任一）：方向轉向有選項取捨／角色邊界重新定義／資源重配或人員決策／跨部門結構調整。
- 識別到就說「這可以建決策案例」，依 `_templates/決策案例.md` 起草
- 判斷理由與「這次判斷贏在哪」要使用者確認後才寫定；回驗欄留空，事後再補
- 確認後存入 `03-決策案例庫/YYYY-MM-DD_主題.md`，並登記進 `DECISIONS.md`
- 懸而未決的事 → 列為候選，使用者確認後登記進 `DECISIONS.md` 對應分類（醞釀型／擱置型／結構性）

### 步驟 4｜盲點四視角（選用，管團隊或有交接議題的使用者適用）
1. **接班／替代**：如果使用者不在這個位置，這件事怎麼繼續？
2. **下游依賴**：使用者停止輸入，誰的工作會停？他知道嗎？
3. **時間衰退**：相關決策的前提現在還成立嗎？
4. **反向確認**：使用者在補誰的位，而對方不知道？

只報**結構性新發現**，不重複已知。找到的列為候選，使用者確認後才寫進 `DECISIONS.md`；時間衰退型附「繼續／修正／放棄」建議與現況證據。

### 步驟 5｜寫回與收尾
- **TASKS.md（三桶，粗顆粒）**。完整行動清單留在會議記錄，TASKS 只收跟使用者有關的：
  1. **先對帳再寫**。新增任何一條之前，先讀 TASKS 🎯／🗓／👀 裡跟這份逐字稿相關的人與主題。逐字稿顯示已完成 → 刪掉那行，CHANGELOG 加一行（`完成：… 來源 [[會議記錄]]`）；有變化 → 原地改寫那行並更新 `(更新 MM-DD)`。同一個主題不另開第二行。
  2. **🎯 我要做**：只放使用者自己要拍板、要寫、要回的事。上限 8 條，超過就在回報裡說，不默默加。
  3. **🗓 我要開的會**：需要使用者召集或當面收斂的，寫成該場會議標題下的議題（沒有就新建標題）。
  4. **👀 我在追**：一人一行。更新那個人的那一行；最多 3 個未結承諾，各附期限。只收使用者會驗收、或會影響使用者對上承諾的事；別人的例行動作留在會議記錄。
  5. 每一條動過的行，結尾標 `(更新 MM-DD)` 和會議記錄連結。
- **人物判斷**：單一事件的人物推論不直接寫進人物圖譜；跨事件、使用者確認過的穩定判斷才補進人物圖譜，並連回依據的會議記錄。
- **CHANGELOG**：改了哪些檔 → `CHANGELOG.md` 頂部加一行（日期＋一行＋連結）。
- **出處分級閘門**：本流程建立或修改的檔，frontmatter 都要有 `author`（本人／AI 標模型名／混合）與 `證據等級`（A/B/C）。流程產出多半是 B/C，B/C 必附 `source` 連回原話或逐字稿檔。定義見 schema.md。

## 結尾統一回報（固定格式）

```
📥 入庫完成
- 專名消歧：[N 個核對／M 個標 ASR待正名／無疑義]（待補登記表：[新變體 或 無]）
- 會議記錄：[檔名 或 N/A]
- 週記：+N 條
- TASKS：[對帳結果：刪 N／改 N／新增 N；🎯 目前 N/8]
- 決策案例候選：[標題，待確認 或 無]
- 盲點掃描：[結構性新發現 或 無新發現 或 N/A]
- 其他寫回：[DECISIONS／人物圖譜 變動]
```

## 硬規則
- 無條件觸發，不被「記過了」「跑新的」「記一下就好」等指令旁路。
- 不 echo 輸入內容，直接給判斷與產出。
- **語氣三不**：
  - (a) 不堆術語。寫成使用者會講給同事聽的話，不是顧問報告。人物觀察用具體行為（「他在會上沒回應這個問題」），不用診斷標籤（「展現迴避型溝通模式」）。
  - (b) 不捧不評。「與會者行為紀錄」記做了什麼和直接效果，不稱讚、不打分、不排名（「說服力強」「全場關鍵」「表現強／弱」都不寫），對使用者本人也一樣。
  - (c) 不用 AI 造的標籤。記憶檔裡的內部標籤、AI 生成的分類法只供檢索，不寫進入庫產出；需要命名時，用使用者或說話者在逐字稿裡實際用的詞。
- 涉及使用者主觀判斷的內容（決策理由、人物評價）標「待確認」，不擅自定稿。
- **庫裡沒有的組織／政治事實，停下來問，不靠側寫推論**。標「待確認」不能拿來當猜的理由。推論被打回時，下一步是問，不是換個方向再推；發現自己對同一件事寫出第二種推論版本，就停下來問。
- **原話必存**：人物／關係判斷密集的輸入（人事衝突、動機推測、定位或接班）→ 原始逐字稿或群聊全文必須存進 `02-日常運作/raw/`（`YYYYMMDD_主題_raw.md`），不是可存可不存。原話是資產，本流程產出的會議記錄、決策案例是衍生物；衍生檔 `source` 連回原話檔。
